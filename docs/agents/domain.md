# 领域文档（Domain Docs）

定义工程与架构类技能在探索和修改代码库时，如何理解并使用本仓库的业务领域术语和既定架构决策。

## 探索代码库前应阅读的文档

- 仓库根目录下的 **`CONTEXT.md`**（业务概念定义与统一领域语言词汇表）。
- **`docs/adrs/`**（或 `docs/adr/`）目录——阅读与你即将改动的模块相关的架构决策记录（ADR）。

如果以上文件或目录尚不存在，**请保持静默并直接继续工作**。无需主动报错或要求用户预先创建。在通过 `/grill-with-docs` 明确术语或决策后，会逐步补全这些文件。

## 目录结构（File Structure）

单上下文模式（Single-context）：

```
/
├── CONTEXT.md
├── docs/adrs/
│   └── 0001-generator-conventions.md
└── packages/
```

## 使用术语表中的统一语言（Glossary's Vocabulary）

在输出中命名领域概念时（包括 Issue 标题、重构建议、设计假设、测试用例命名等），必须严格使用 `CONTEXT.md` 中定义的术语，避免使用术语表中未收录的近义词或自造词汇。

如果需要的概念在术语表中尚未收录，这通常意味着：

1. 正在引入项目不使用的生僻语言（应重新审视并统一）；
2. 确实存在领域语言空白（可使用 `/grill-with-docs` 记录并补充）。

## 标记 ADR 冲突（Flag ADR Conflicts）

如果输出方案与已有的 ADR 存在冲突，必须明确标出并给出理由，而不是静默覆盖：

> _与 ADR-0001 (generator conventions) 存在冲突——但值得重新讨论，原因是……_
